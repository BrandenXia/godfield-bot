# ADR 0015: Live resource shadow readiness gate

- Status: **Accepted**
- Date: 2026-09-09
- Amends: ADR 0005, ADR 0010, and ADR 0014

## Context

The schema-v5 resource candidate passed its paired native curriculum gate and
can now make non-executable proposals from private API observations. A live
evidence gate must reject stale schema-v4 runs, malformed trajectories, and
small or unrepresentative samples. It also must not attribute match outcomes to
the candidate: the tactical heuristic executes every command during shadow
collection.

## Decision

Add `live-resource-shadow-readiness-v1`, an immutable report generated by
`models evaluate-live-shadow`. Evaluation requires the exact passing native
resource report and validates its candidate ID, weight checksum, parent model,
training simulation contract, client, vocabulary, observation schema, ruleset,
both expected matchup identities, game totals, and verdict consistency.

Only private runs with all of the following identities are admitted:

- the candidate model ID and immutable weight checksum;
- feature schema v5 and `api-resource-neural-shadow-v2`;
- `api-combo-utility-heuristic-v1` as the behavior policy;
- the model ID attached directly to the run record.

Within each admitted run, every normalized state must be followed by its legal
action set, exactly one v2 shadow decision, and exactly one behavior decision in
that order. Digests, action membership, model identity, non-executable shadow
status, and neural selection traces are checked. A completed game requires an
adjacent, consistent classified terminal outcome and sparse terminal reward.
Continuous sessions may contribute several games; interrupted in-progress
games remain visible in the completion rate.

The default gate requires:

- 20 completed games and a 0.75 lower confidence bound on completion;
- 40 actionable attack turns and 20 defense opportunities;
- 12 actionable resource-bearing turns, including at least one HP sundry, MP
  sundry, fixed-attack miracle, and HP miracle opportunity;
- 0.50 lower bounds on overall proposal coverage and resource-state coverage;
- 0.60 overall and 0.50 resource-state lower bounds on exact agreement with the
  tactical behavior policy;
- no evidence-integrity errors, failed matching runs, or operational aborts
  (`action_limit`, `no_progress_limit`, `unclassified_terminal`, or
  `unsupported_self_turn`).

All proportions use a Wilson lower bound with `z=1.96`. Resource opportunities
respect native caps, so HP recovery at 100 HP and MP recovery at 100 MP do not
inflate the denominator. Counts, exclusions, up to 20 integrity errors, outcome
diagnostics, thresholds, source run IDs, and a digest of every admitted run and
event are stored in an owner-only report.

The runtime now attaches the shadow model ID to the run record as well as its
config, closing an attribution ambiguity in older evidence. The live neural
adapter also maps armor-less defense to the native Forgive action and verified
API pass, rather than recording a false curriculum abstention.

## Consequences

A passing report means the candidate has enough intact, representative shadow
evidence to enter a separately designed and explicitly authorized controlled
trial. It does not show that the candidate would have achieved the recorded
wins or losses, because those belong to the behavior heuristic.

Accordingly, every report has `promotion_eligible: false`, even when `passed`
and `ready_for_controlled_trial` are true. Learned live execution still requires
a new canary protocol, candidate-controlled outcome evidence, rollback rules,
and explicit operator authorization. Threshold overrides are recorded in the
input digest and cannot silently change the meaning of an existing report.
