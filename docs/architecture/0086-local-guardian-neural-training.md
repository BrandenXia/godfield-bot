# ADR 0086: Separate local recurrent duel training

## Status and boundaries

Accepted, 2026-09-29. The user continued after the recommendation to start
duel-only with a separate checkpoint. This implements local learning for the
94-model, synthetic-deal, provisional arena, not full official-game fidelity.
Neither existing live/checkpoint schemas nor previous training curricula change.

The policy identity is `numeric-slot-recurrent-guardian-arena-v1`; the algorithm
is `provisional-guardian-duel-recurrent-imitation-ppo-v1`. It accepts the seven
policy projections from arena observation schema 1. Catalog IDs are embedding
tokens (297 entries including empty zero against the pinned 296-model API
catalog); only the 94 supported inventory models are dealt. Allocating embeddings
does not implement or train the remaining mechanics.

## Architecture and learning

Own cards combine embeddings with seven numeric features, including cost and
selection. The network keeps separate self/enemy public-player summaries,
encodes global context, and uses a GRU. Shared slot and target scorers preserve
the 18-slot/30-action layout without learning fixed absolute seat identities.
Only policy projections are tensorized; bookkeeping and hidden inventories are
excluded. Illegal actions are masked; terminal rows are never inferred.

Imitation provides a warm start from the legal greedy smoke baseline. Selected
defense states can be upweighted: early experiments showed that high overall
accuracy concealed repeated selection/deselection loops. The CLI defaults to
64 teacher updates with weight 4 for these states; direct configuration defaults
the weight to 1 for compatibility with earlier exploratory records. The network
retains every native legal action, including deselection: there is no hidden
teacher fallback or action shield during neural evaluation.

PPO follows with current-policy self-play and a configurable fraction of
baseline-opponent environments. Learner seats alternate by episode; overridden
baseline actions are excluded from the policy and entropy losses. Critic targets
use the existing signed two-player zero-sum GAE. Three-plus-player training is
explicitly rejected. Wins and absorbing turn/toggle/decision truncations stop
GAE and bootstrap to zero, as required by ADR 0085.

Episodes and detached independent seat memories persist across update windows.
Each rollout stores its initial memories and episode-start flags. Recurrent
minibatch replay reproduces old logits/values, including across window boundaries.
Backpropagation is truncated at the stored initial memories; carried memories
were generated by the previous policy version, not recomputed from full history.

CPU-only training currently limits storage to 32,768 decisions per rollout and
4,096 per recurrent minibatch. Losses, gradients, saved weights, and metrics must
be finite. CPU thread count and global Torch RNG state are restored on exit.
Progress logs report warm-start accuracy, selected-defense accuracy, PPO loss,
and separate completions/truncations.

## Checkpoints and evaluations

Checkpoints are new UUID directories under `checkpoints/guardian-arena`, with
private files `arena-manifest.json` and `arena-weights.pt`, published atomically.
They are not compatible with `models load` or live control. Checksums, explicit
identities, source pins, architecture, complete update/decision counts, finite
metrics, and complete evaluation accounting are checked. Deserialization uses
Torch's weights-only path. Resume creates a new checkpoint and records the
parent checksum; optimizer state is intentionally fresh, not an exact resume.
Changed observation/source/native/curriculum/reward contracts are rejected.

Before and after learning, deterministic raw-neural play is evaluated against
the baseline on the same disjoint seed. Each initial hand/guardian opening is
played with the learner in both seats. Baseline-versus-baseline is a separate
calibration reference. All attempted games remain in the win denominator;
truncations are classified as turn, defense-selection, or decision limits.
These are diagnostic/development evaluations, not a promotion gate.

`simulation guardian-train` trains and writes the separate checkpoint;
`simulation guardian-evaluate` is read-only and source-pinned. A tested run is:

```bash
UV_CACHE_DIR=.uv-cache uv run --frozen --extra simulation --extra training \
  godfield-bot simulation guardian-train \
  --batch-size 32 --rollout-steps 64 --teacher-updates 64 \
  --teacher-selected-defense-weight 4 --updates 10 \
  --max-turns 32 --max-decisions 128 --evaluation-games 32
```

Checkpoint `420b053f-9554-4491-8da2-b3efeb185720` has weight checksum
`7138612cc9dc21089b731ad49f791f8227ca779f856088c8214372edbf75fa19`.
It trained on 131,072 imitation and 20,480 PPO decisions. On seed 1,000,070,
the untrained policy had 31 toggle-limit exits and one turn-limit exit in
32 games. The candidate had four wins, seven losses, and 21 turn-limit exits,
with no toggle/decision-limit exits. Baseline-versus-baseline had four wins,
four losses, and 24 turn-limit exits. Additional paired evaluations on seeds
2,000,070 and 3,000,070 respectively had 7/11/46 and 9/10/45 wins/losses/turn
limits in 64 games each, again with no toggle/decision-limit exits.

This supports local learning and a reduction in policy loops on those sets,
not reliable superiority to the baseline or readiness for humans/official bots.
Full-game readiness, official verification, and promotion remain false.

The 26 new training tests cover shapes, masks, numeric-feature gradients, card
permutation, memory replay, absorbing boundaries, imitation/PPO learning,
paired evaluations, private/checksummed checkpoints, deterministic training,
resume isolation, tamper rejection, subgroup metrics, and source-pinned CLI
evaluation. All 1,230 non-browser regressions, lint/format, strict typing of
72 modules, and lock/whitespace checks passed for this milestone.
