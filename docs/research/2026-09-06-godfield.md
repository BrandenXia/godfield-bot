## Client and account behavior

- The web client is a Dart application rendered as ordinary, absolutely
  positioned DOM elements in a logical 1080×720 viewport. It is not a canvas.
  Text, inputs, image asset paths, and click targets can therefore be observed
  without OCR in the current build.
- The public page loads `main.dart.js`, Firebase 12.17.1 modules, and Google
  Analytics. The client bundle initializes Firebase anonymous authentication,
  Firestore, and callable cloud functions.
- The entry screen asks for a Prophet Name (maximum 18 characters) and offers
  Genesis. The requested name `ロキ-67` fits.
- The client contains Training, Private, and Duel modes. The official store
  description says the game supports up to nine players.
- No public API documentation or automation policy was found on the official
  website or either store listing. Internal service names visible in a shipped
  client are not a public API contract and should not be used by the bot.
- The official website exposes a privacy policy and an account-deletion
  control, but no separate terms/automation page was located. Absence of such
  a page is not permission for unattended public matchmaking.

The identity is effectively a Firebase anonymous account tied to browser
storage, not a conventional username/password login. A consistent bot should
therefore use one dedicated persistent Chromium profile. That profile is a
credential: it must live outside Git with owner-only permissions and be backed
up only through an encrypted, explicit operator flow.

## Current rules useful to perception and action validation

The live Bible states:

- Non-element attacks can be defended by any element.
- Fire is defended by Water; Water by Fire; Wood by Stone; Stone by Wood.
- Light cannot be defended by any element.
- Darkness can be defended by any element, but damage reduces HP to zero.
- Combining different elements yields Non-element.
- Light can substitute for Fire, Water, Wood, or Stone.
- Diseases naturally worsen each turn with a 5% chance and worsen when
  another disease is caught.
- Under Fog, using an artifact on an enemy chooses the target at random.
- Weapons, Sun Amulet, and Dangerous Mortar cannot be discarded.
- After the Apocalypse, Discard becomes Sacrifice.
- Miracles consume MP, are reusable, and are not subject to Sell, Buy, or
  Nocturnal Broom.
- A bounced attack goes to somebody.
- Earth God uses trade, weapons, armor, and sundries; Moon God uses miracles.
- Guardians act after an enemy turn with a 25% chance and leave with a 10%
  chance when damaged.
- After the Apocalypse, a devil has a 25% chance to appear whenever an
  artifact is given.

## Automation implications

1. Use semantic text/input/image observations first and screenshots only as a
   diagnostic or visual fallback. Coordinate-only automation would be brittle
   because the logical viewport is scaled to the available browser area.
2. Treat asset paths (for example, `/images/items/weapons/bronze-club.webp`)
   as useful observation features, but version them against the bundle hash.
3. Maintain a selector contract test that opens the public Bible and verifies
   category counts before allowing a game run.
4. Fail closed on an unknown screen, count drift, duplicate/ambiguous target,
   timeout, CAPTCHA, interstitial, or loss of account state.
5. Do not inspect, call, or emulate undocumented Firebase/cloud-function
   endpoints. The production adapter should exercise only the visible web UI.

## Implemented data refresh

`godfield-bot data refresh` now replays the browser extraction into normalized,
versioned JSON, validates every detail panel, separates common category notes,
and fingerprints the shipped client bundle. A semantic diff command remains
to be added before automated refreshes are accepted. Gameplay state/action
schemas require one operator-approved account creation and a read-only
observation session in Training mode.
